# Примеры использования Playwright MCP с админкой

Этот документ содержит практические примеры использования Playwright MCP сервера для тестирования и анализа FunnyEnglish Admin Panel.

## Что такое MCP?

MCP (Model Context Protocol) позволяет Claude взаимодействовать с браузером через Playwright напрямую. Это значит Claude может:

- Открывать страницы и делать скриншоты
- Кликать по элементам и заполнять формы
- Анализировать DOM и стили
- Проверять console errors и network requests
- Генерировать тесты на основе действий

## Примеры запросов к Claude

### 1. Базовая проверка страницы логина

```
Перейди на http://localhost:5173/login и проанализируй:
1. Какие поля формы доступны?
2. Есть ли валидация на клиенте?
3. Какой дизайн используется (Material UI, кастомный)?
4. Есть ли accessibility атрибуты (aria-labels)?
```

### 2. Тестирование авторизации

```
Открой http://localhost:5173 и протестируй логин:
1. Введи email: admin@funnyenglish.com, password: admin123
2. Нажми кнопку входа
3. Проверь что произошел редирект на дашборд
4. Проверь что отображается имя пользователя
5. Сделай скриншот дашборда
```

### 3. Анализ компонентов дашборда

```
Залогинься в админку (admin@funnyenglish.com / admin123) и проанализируй:
1. Какие компоненты используются на дашборде?
2. Есть ли графики/чарты? Какая библиотека?
3. Как организована навигация?
4. Какие цвета используются в UI?
5. Соответствует ли дизайн Material Design 3?
```

### 4. Тестирование CRUD операций

```
Залогинься и протестируй создание пользователя:
1. Перейди в раздел Users
2. Нажми кнопку "Add User"
3. Заполни форму тестовыми данными:
   - Name: Test User MCP
   - Email: test-mcp@example.com
   - Role: Student
4. Сохрани и проверь что пользователь создан
5. Удали тестового пользователя
```

### 5. Responsive Design Testing

```
Проверь адаптивность админки:
1. Открой дашборд при разрешении 1920x1080
2. Сделай скриншот
3. Измени размер на 1366x768 (ноутбук)
4. Сделай скриншот
5. Измени размер на 375x667 (мобильный)
6. Сделай скриншот
7. Опиши как меняется layout на разных размерах
```

### 6. Performance Analysis

```
Проанализируй производительность:
1. Открой дашборд
2. Измерь время загрузки страницы
3. Проверь console на warnings/errors
4. Проанализируй network requests - есть ли лишние запросы?
5. Проверь размер загружаемых ресурсов
```

### 7. Accessibility Audit

```
Проведи accessibility аудит страницы логина:
1. Проверь наличие aria-labels
2. Проверь contrast ratio для текстов
3. Проверь навигацию с клавиатуры (Tab, Enter)
4. Проверь работу с screen reader (если возможно)
5. Дай рекомендации по улучшению a11y
```

### 8. Форма с валидацией

```
Протестируй валидацию формы создания курса:
1. Открой форму создания курса
2. Попробуй сохранить с пустыми полями
3. Проверь сообщения об ошибках
4. Заполни поля невалидными данными (слишком короткое название)
5. Проверь валидацию email если есть
6. Опиши UX валидации
```

### 9. Генерация тестов из действий

```
Запиши мои действия и сгенерируй тест:
1. Открой страницу логина
2. Введи учетные данные
3. Нажми вход
4. Перейди в Settings
5. Измени язык на English
6. Сохрани

На основе этих действий сгенерируй Playwright тест.
```

### 10. Сравнение состояний

```
Сравни UI до и после:
1. Залогинься, сделай скриншот дашборда
2. Переключи на темную тему (если есть)
3. Сделай скриншот
4. Сравни два скриншота - что изменилось?
```

## Расширенные сценарии

### Интеграция с API

```
Комбинируй UI и API тесты:
1. Через API создай тестового пользователя
2. Через UI проверь что он отображается в списке
3. Через UI отредактируй пользователя
4. Через API проверь что изменения сохранились
```

### Тестирование ошибок

```
Проверь обработку ошибок:
1. Отключи сеть (simulate offline)
2. Попробуй сохранить форму
3. Проверь сообщение об ошибке
4. Включи сеть обратно
5. Проверь retry логику
```

### Многопользовательские сценарии

```
Симулируй многопользовательский сценарий:
1. Открой два окна браузера (контекста)
2. Залогинься как Admin в первом
3. Залогинься как Student во втором
4. Admin создает задание
5. Student видит новое задание (real-time update?)
```

## Советы по написанию промптов

### ✅ Хорошие практики

```
"Перейди на localhost:5173, залогинься с учетками test/test123,
открой страницу Users, отсортируй по email и сделай скриншот"
```

- Конкретный URL
- Точные учетные данные
- Четкие шаги
- Ожидаемый результат

### ❌ Избегайте

```
"Проверь админку"
```

- Слишком общий запрос
- Нет конкретики
- Непонятно что проверять

## Дебаг с MCP

### Получение информации о странице

```
Покажи мне:
1. Текущий URL
2. Title страницы
3. Все кнопки на странице
4. Все ссылки
5. Console errors если есть
```

### Проверка селекторов

```
Проверь доступность элементов:
1. Можно ли найти кнопку "Save" по тексту?
2. Можно ли найти по data-testid?
3. Можно ли найти по aria-label?
4. Какой селектор самый стабильный?
```

## Интеграция с CI

```
Запусти все E2E тесты и:
1. Запиши видео упавших тестов
2. Сделай скриншоты ошибок
3. Сохрани trace файлы
4. Сгенерируй HTML отчет
```
