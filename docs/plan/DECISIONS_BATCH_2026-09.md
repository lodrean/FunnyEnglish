## 1. Повторная Practice после REVIEWED (bd qbq.1 + h3l.2)

> **РЕШЕНИЕ (2026-09-06): разрешить.** После REVIEWED повторная отправка разрешена (снятие 409 при оценённом топике). Реализация — bd h3l.2 (остаётся открытой как имплементация).

**Противоречие:** PRD и openspec `speaking-practice` разрешают повторные отправки
(«resubmissions SHALL be allowed»), но код с 2026-08-03 (решение bd 7vm) блокирует
вторую отправку: флаг `hasSubmitted` + backend 409 `DUPLICATE_SUBMISSION` + с
2026-08-30 UNIQUE(user_id, topic_id) на уровне БД (V25).

- **Вариант A (рекомендую):** канон = одна Practice-отправка на топик. Бамп
  openspec speaking-practice + PRD: убрать resubmission, задокументировать 409.
  Обоснование: Training уже даёт 3 попытки; Practice = «экзамен»; код стабилен,
  дифф — только текст спек.
- **Вариант B:** разрешить повтор после REVIEWED. Дорого: partial-unique в БД,
  UI-флоу re-practice, повторное ревью, миграция данных.
- **Вариант C:** N попыток как в Training. Меняет продуктовую модель Practice.

**Влияние:** Part 2 §6 (Practice), openspec/speaking-practice, PRD Story 5;
админка: без повторов очередь ревью детерминирована.

## 5. Официальные платформы (bd 5tf.10)

> **РЕШЕНИЕ (2026-09-06): Android-first, остальные стабы.** Статус-кво фиксируется решением; вопрос закрыт до релиза ядра.

Факт: запись/воспроизведение работают на Android; desktop — плеер/запись через
jlayer/AWT; WASM — HTML5-видео, запись no-op; iOS — `iosMain` без
MainViewController, рекордеры-заглушки.

- **Вариант A (рекомендую):** официальные таргеты MVP = Android + WASM (просмотр/
  теория), запись — только Android (задокументировать в Part 2 §3.2); iOS-target
  убрать из KMP (собираться не может), desktop — «best effort» без гарантий.
- **Вариант B:** Android-only, остальные таргеты убрать (wasm e2e уже есть — жалко).
- **Вариант C:** доделать iOS/Desktop запись (дорого: AVAudioRecorder, permissions).
