## 1. Дифф по разделам спеки

### §Version → «Version 3.0 — Playful Coach × Material 3»
- **Что:** bump заголовка + строка ченджлога: «v3.0 · 2026-08-07 — компонентная база Material 3; токены v1.3.0».
- **Почему:** спека описывает базу компонентов; после пересборки на M3 описание v2.1 устарело.
- **Альтернативы:** оставить v2.1 и вести M3-надстройку отдельно — отвергнуто: два источника истины по компонентам неизбежно разойдутся.
- **Влияние:** ссылки на версию в README/ченджлогах.

### §1. Источники истины
- **Что:** версии артефактов: `tokens.json` v1.2.0 → **v1.3.0**; `mockups.html`/`styleguide.html` v1.x → **v2.0**; добавить строки: `docs/design/M3_REPLACEMENT_REGISTRY.md`, `docs/design/M3_IMPLEMENTATION_MAPPING.md`.
- **Почему:** реестр и маппинг — новые обязательные спутники спеки (маппинг, не импровизация в коде).
- **Альтернативы:** встроить реестр в спеку — отвергнуто: реестр — рабочий документ этапа, спека — стабильный контракт.
- **Влияние:** нет на смежные спеки.

### §2. Токены → «Токены (v1.3.0)»
- **Что:**
  - Цвета §2 — **без изменений** (HEX 1:1; это жёсткое ограничение §3.1 брифа).
  - Добавить подраздел «M3-роли (v1.3.0)»: `surfaceContainerLowest…Highest`, `outlineVariant`, `inverseSurface/inverseOnSurface/inversePrimary`, `scrim`, `surfaceTint`, тёмные контейнеры (`primaryContainer #2E3E6E`, `secondaryContainer #46366F`, `recordContainer #59311C` + on-роли), state-layer alpha (hover 8 / focus 12 / pressed 12 / dragged 16 / disabled 38/12), tonal elevation level0–5.
  - §Motion: добавить M3-easing (`m3Standard`, `m3Emphasized`) и `m3DurationState 200ms`; brand recPulse/CheckPopAppear пометить как brand-моушен.
- **Почему:** M3-компоненты требуют этих ролей (индикатор NavigationBar, Snackbar, state layers); без них реализация начнёт выдумывать значения.
- **Альтернативы:** брать дефолтные M3-тона (генерация из seed #5B8DEF) — отвергнуто: ломает фирменную палитру (запрещено §3.1).
- **Влияние на смежные спеки:** `SPEAKING_TRAINER_SPEC_PART*` ссылаются на токены по именам — существующие имена не изменены, обратная совместимость полная.

### §2. Формы и тени
- **Что:** зафиксировать, что кастомные тени заменяются M3 tonal elevation, **кроме** тени rec-кнопки `0 4px 0 rgba(217,114,56,.55)` и focus-ring. Тень `card` остаётся для ElevatedCard (level1) до полного перехода на tonal.
- **Почему:** §4.3 брифа (state layers и tonal elevation вместо кастомных теней).
- **Альтернативы:** убрать все тени сразу — отвергнуто: визуальный скачок без необходимости; rec-тень — brand.
- **Влияние:** конформити-отчёты (скриншоты изменятся — ожидаемо, §7 спеки).

### §2. Типографика
- **Что:** добавить таблицу маппинга DS-размеров на M3-роли (display/headline/title/body/label) — из DSM-5 §2. Размеры и веса — без изменений.
- **Почему:** §4.2 брифа; разработчик видит роль M3, а не выбирает сам.
- **Альтернативы:** принять дефолтный M3 type scale — отвергнуто: меняет размеры (запрещено §3.1).
- **Влияние:** нет.

### §3. Светлая/тёмная тема
- **Что:** дописать dark-контейнеры v1.3.0 и правило «light `primary`-слот M3 = primaryStrong #3B6FD4» (белый текст только на нём).
- **Почему:** M3 по умолчанию кладёт белый на `primary`; при `primary=#5B8DEF` это 3.23:1 FAIL. Правило снимает риск регресса WCAG при механической сборке схемы.
- **Альтернативы:** осветлить белый текст/затемнить primary — отвергнуто: меняет палитру.
- **Влияние:** admin-web `Theme.ts` (dark-палитра L544), compose `SpeakingTokens.kt`.

### §4. Реализация
- **Что:** заменить перечень кастомных компонентов (`SpeakingPrimaryButton/Ghost/DangerGhost`, `SpeakingField`, кастом-карточки) на M3-маппинг со ссылкой на DSM-5; явно перечислить оставшийся brand-кастом: rec-кнопка (B1), таймер-кольцо (B2), waveform (B3), ThemeCover (B4), CheckPopAppear/recPulse (B5/B6), REC-индикатор (B7).
- **Почему:** §4.1/§3.3 брифа: стоковые M3/MUI без кастомной магии; кастом — только осознанный brand.
- **Альтернативы:** оставить кастомные компоненты как есть — отвергнуто: это и есть предмет редизайна.
- **Влияние:** план реализации (отдельный, после утверждения дизайна); текущий код не трогаем (§8.3).

### §5. Поведенческие требования
- **Что:** **без изменений** (§3.2 брифа авторитетен; в mockups v2.0 аннотации перенесены дословно).
- **Влияние:** нет.

### §6. Доступность (WCAG)
- **Что:** добавить новые проверенные пары из v1.3.0 (inverse-пара Snackbar ≈11:1; dark-контейнеры) и правило из §3 выше; существующие пары — без изменений, деградации нет.
- **Почему:** новые роли = новые сочетания, они обязаны быть зафиксированы с контрастами.
- **Влияние:** конформити-чеклист (доп. строки проверки).

### §7. Дизайн-конформити
- **Что:** обновить источник сверки: mockups **v2.0** (15 фреймов, light+dark), styleguide **v2.0**; процедура та же.
- **Влияние:** `docs/qa/design-conformance/` — следующий прогон будет против v2.0-мокапов.

### Приложение A (архив v1.0)
- **Что:** без изменений; при необходимости добавить строку «v2.x (Playful Coach до M3) — в git-истории».
