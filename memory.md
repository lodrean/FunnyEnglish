## 1. Архитектура проекта

Кроссплатформенное приложение для изучения английского с геймификацией. Монорепо:

- `backend/` — Spring Boot 3.4.1 (Kotlin 2.1.0, Java 21), PostgreSQL + Flyway, JWT (jjwt 0.12.6), S3/MinIO для медиа. Порт 8080.
- `admin-web/` — React 18 + TypeScript + MUI 6 + TanStack Query 5 + react-router-dom 6, Vite 5. Порт 3000.
- `composeApp/` — ОСНОВНОЙ KMP-модуль UI (android/ios/desktop/wasmJs). Монолит: весь рабочий код в `app/screens/*`, `app/viewmodel/*`, `app/di/*`.
- `app/` — тонкая Android-обёртка (`SoToSpeakApplication` + `MainActivity`).
- `shared/` — KMP: `api/SoToSpeakApi.kt` (Ktor-клиент), модели, `GuestProgressRepository`.
- `core/`, `core:domain`, `core:data`, `core:presentation` — инфраструктура (DI, HttpClientFactory, Result/UiText, общие UI-компоненты).
- `feature-api` + `feature-*` — целевая модульная архитектура (Clean Architecture по фичам). **ВАЖНО: в composeApp не подключены; `:feature-tests` пустой.** Новый код писать в composeApp, если нет явной задачи на миграцию (ADR-006).
- `design/` — дизайн-система KMP (Material 3).
- Навигация: ручная БЕЗ NavHost — `sealed class AppScreen` + `mutableStateOf` в `composeApp/.../app/App.kt`. (В feature-api задуман navigation-compose 2.8 + `FeatureNavigator`, не используется.)

## 2. Конвенции кода

- **DI — Koin 4.0.0.** Паттерн: `val xxxModule = module { single { ... }; viewModel { ... } }` (пример: `composeApp/.../app/di/AppModule.kt`). Старт НЕ через `startKoin`, а `KoinApplication { modules(appModule) }` в `App.kt`; VM через `koinViewModel()`. Платформенный конфиг — expect/actual `provideAppConfig()`.
- **Presentation — MVI на StateFlow.** Тройка файлов на экран: `XxxState.kt` (data class), `XxxAction.kt` (sealed), `XxxEvent.kt`; ViewModel: `MutableStateFlow(State())` + `Channel<Event>.receiveAsFlow()` + `fun onAction(...)` с when. Пример: `feature-home/.../presentation/HomeViewModel.kt`. Ошибки — `UiText?`.
- **Data — Ktor 3.0.2 + safeCall + Result.** Repository: `override suspend fun getX(): Result<X, DataError.Network> = safeCall { api.getX() }` (пример: `feature-home/.../data/HomeRepositoryImpl.kt`). Json: `ignoreUnknownKeys=true, isLenient=true`. Токен — `PersistentTokenProvider` (multiplatform-settings, ключ `auth_token`). Картинки — Coil 3.
- **Типы-обёртки**: рабочие `Result`/`DataError` лежат в `core/domain/util/` — импортировать оттуда (в `core/domain/` есть устаревшие дубли!).
- **Комментарии и коммиты** — по существу; документация на русском в `docs/`.
- Admin-web: страницы в `src/pages/`, API в `src/api/client.ts` (axios, токен в localStorage), E2E в `e2e/` (Playwright, Page Object в `e2e/pages/`).

0. **Fullscreen edge-to-edge vs display cutout: ДВА независимых letterbox'а** (2026-08-12, поймано скриншот-гейтом fullscreen): (а) `layoutInDisplayCutoutMode=DEFAULT` в landscape+immersive letterbox'ит окно вне зоны выреза — нужен `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` на время fullscreen (API 28+, restore в DEFAULT); (б) даже с shortEdges остаётся полоса ровно шириной cutout-inset (у Pixel 7 = 136px) цвета Scaffold containerColor — это `padding(padding)` корневого Scaffold в `App.kt MainAppContent` (дефолтные `contentWindowInsets` M3 включают displayCutout; в immersive systemBars=0, а cutout НЕ обнуляется никогда). Фикс: для `AppScreen.Video` внешний padding не применяется — экран видео сам управляет insets. Диагностика: пиксельный скан скриншота (граница светлой зоны = cutout inset) + `dumpsys window windows | grep layoutInDisplayCutoutMode` + `dumpsys display | grep cutout`. - 2026-08-30 → **Полноценные refresh-токены на backend** (bd `FunnyEnglish-nj2.7`, SEC §2.1 п.6 / AR-6). Схема «refresh = обмен истёкшего access-токена в 7-дневном окне» УДАЛЕНА. Теперь: refresh — отдельный JWT (claim `type=refresh`, уникальный JTI, TTL `app.jwt.refresh-expiration`, env `JWT_REFRESH_EXPIRATION`, дефолт 7 дней; свойство `refresh-window`/`JWT_REFRESH_WINDOW` убрано); в БД (`refresh_tokens`, Flyway V26) — только SHA-256-хэш + jti + rotated_at/revoked_at. Ротация при каждом `/auth/refresh` (токен одноразовый); reuse-detection: повторное предъявление ротированного/отозванного токена → отзыв ВСЕХ refresh-токенов пользователя + 401. `POST /auth/logout {refreshToken}` — отзыв, идемпотентный (всегда 200). `AuthResponse`/`RegisterResponse` получили поле `refreshToken`. Refresh-токен НЕ работает как Bearer access (фильтр отсекает `type=refresh`). **Роль сверяется с БД** в `JwtAuthenticationFilter` (claim `role` игнорируется), кэш userId→role 60с — понижение роли действует без перевыпуска токена. **HTTP-семантика**: аноним на защищённом пути → 401 `UNAUTHORIZED` (было 403), неверные креды login → 401 `INVALID_CREDENTIALS` (было 400), невалидный refresh → 401 `INVALID_REFRESH_TOKEN`; аутентифицированному без роли по-прежнему 403; `EMAIL_NOT_VERIFIED` остаётся 403. **Follow-up (требует отдельной задачи/спеки, ADR-007)**: клиент `shared/api/SoToSpeakApi.kt` шлёт в `/auth/refresh` СТАРЫЙ ACCESS-токен → после деплоя авто-refresh перестанет работать (401 → сброс сессии при истечении access) — нужно хранить refreshToken и слать его; `docs/API.md` §POST /auth/refresh описывает старый контракт — требуется правка спеки владельцем.

- 2026-08-19 → **Механизм рефреша токена (минимальный, bd `FunnyEnglish-db9`)**. Причина: истёкший access-токен (TTL 24ч) ломал даже ПУБЛИЧНЫЕ эндпоинты — `JwtAuthenticationFilter` отдавал 401 TOKEN_EXPIRED до authorization-слоя, хотя `/public/**` permitAll (логи 2026-08-18: 401 на `/api/public/speaking/libraries`, `/api/public/logs`). Решение: (1) фильтр при истёкшем/невалидном токене продолжает цепочку как аноним + ставит request attribute `TOKEN_EXPIRED`; 401 с `code=TOKEN_EXPIRED` отдаёт только `authenticationEntryPoint` в SecurityConfig на защищённых путях (без токена — прежний 403, чтобы не ломать существующие тесты/контракты). (2) `/auth/refresh` (уже существовал, принимает сам access-токен) ограничен окном `app.jwt.refresh-window` (env `JWT_REFRESH_WINDOW`, дефолт 7 дней после exp) — раньше истёкший токен продлевался бесконечно. (3) KMP-клиент: `safeCall` на 401 → single-flight refresh (Mutex) → один retry (header подхватывается в defaultRequest); неудача → токен очищен + `onSessionExpired` → AuthViewModel через `SessionEvents`-single (мост single→viewModel без циклической зависимости) сбрасывает UI в гостевой режим (гостевая сессия НЕ чистится). Auth-эндпоинты (login/register/oauth) — без refresh-retry (`safeCallNoRefresh`). (4) `SoToSpeakApi` получил опциональный `httpClientEngine` для MockEngine-тестов (ktor-client-mock в commonTest). Тесты: backend `TokenRefreshIntegrationTest` (6 кейсов), composeApp `SoToSpeakApiTokenRefreshTest` (3 кейса, MockEngine). Admin-web не тронут (redirect на /login при 401). Полноценные refresh-токены (таблица, ротация, отзыв) — отдельной задачей через OpenSpec при решении владельца. План: `~/.kimi/plans/jean-grey-wolverine-america-chavez.md`. **Важная находка по ходу**: Ktor 3.0.2 НЕ бросает исключения на не-2xx по умолчанию (expectSuccess=false) — ошибки уходили в generic-ветку safeCall с кодом 0 и сырым JsonException (объясняет граблю №15); в `SoToSpeakApi` включён `expectSuccess = true`, теперь ApiException получает реальный HTTP-код. **Того же дня**: краш Android `FadingEdgeText` — `style.lineHeight` (Sp) → `toDp()` = IllegalStateException «Only Sp can convert to Px»; фикс — Sp конвертируется через `toPx().toDp()` (bd `FunnyEnglish-6tx`).
