# Delta spec: speaking-content (change add-speaking-backend)

## Purpose

Контентная модель speaking-тренажёра (libraries → topics → videos/speaking_questions) и её выдача: публичная для гостей и CRUD для администратора. Детали реализации — `docs/SPEAKING_TRAINER_SPEC_PART1.md` v1.0.

## ADDED Requirements

### Requirement: Хранение контентной иерархии
Система SHALL хранить контент в иерархии: library (тема) 1—* topic 1—1 video и 1—* speaking_question. Топик SHALL поддерживать soft delete (архивацию) без физического удаления. Видео SHALL хранить публичный URL mp4/webm-файла и опциональный URL WebVTT-субтитров; URL субтитров равен NULL означает, что режим «с субтитрами» недоступен на клиенте.

#### Scenario: Создание топика с видео и вопросами
- **WHEN** администратор создаёт library, затем topic в ней, загружает video с субтитрами и добавляет вопросы
- **THEN** вся иерархия сохраняется со связями, и топик доступен для публикации

#### Scenario: Архивация топика с записями учеников
- **WHEN** администратор удаляет топик, к которому существуют practice-записи учеников
- **THEN** топик помечается архивным (soft delete), записи учеников и их оценки сохраняются, топик исчезает из публичной выдачи, но остаётся видимым администратору как архивный

### Requirement: Публичная выдача контента гостю
Система SHALL предоставлять неавторизованным пользователям read-only API контента: список тем, список топиков темы, детали топика (видео, субтитры, вопросы). Публичная выдача MUST включать только опубликованные (`is_published`) и не архивированные сущности. Темы без опубликованных топиков MUST быть скрыты из выдачи. Все медиа-URL в ответах MUST быть публичными (внутренний hostname хранилища не утекает наружу).

#### Scenario: Гость получает список тем
- **WHEN** гость запрашивает список тем без токена
- **THEN** возвращаются только опубликованные темы, имеющие хотя бы один опубликованный неархивный топик, с количеством таких топиков, отсортированные по display_order

#### Scenario: Гость запрашивает неопубликованный топик
- **WHEN** гость запрашивает детали топика, который не опубликован, архивирован или принадлежит неопубликованной теме
- **THEN** возвращается 404 «Topic not found» (существование топика не раскрывается)

#### Scenario: Топик без видео
- **WHEN** гость запрашивает опубликованный топик, к которому видео ещё не загружено
- **THEN** ответ содержит `video: null` и список вопросов (клиент ведёт ученика сразу к вопросам)

### Requirement: Административный CRUD контента
Система SHALL предоставлять администратору (ROLE_ADMIN) полный CRUD над libraries, topics, videos и speaking_questions, включая неопубликованные и архивные сущности. Удаление топика SHALL быть мягким (идемпотентным). Замена видео/субтитров SHALL удалять старые файлы из хранилища (best-effort, без отката транзакции). Физическое удаление темы, к топикам которой есть practice-записи, MUST быть отклонено с ошибкой 400 и подсказкой архивировать топики.

#### Scenario: Публикация топика
- **WHEN** администратор создаёт топик (по умолчанию `isPublished=false`), затем публикует его
- **THEN** до публикации топик невидим в публичной выдаче, после публикации — виден гостю

#### Scenario: Повторное удаление топика
- **WHEN** администратор повторно удаляет уже архивированный топик
- **THEN** операция завершается успешно (идемпотентно), топик остаётся архивным

#### Scenario: Удаление темы с записями учеников
- **WHEN** администратор пытается физически удалить тему, к топикам которой существуют practice-записи
- **THEN** возвращается 400 с сообщением о необходимости архивировать топики, данные не удаляются

### Requirement: Загрузка медиафайлов контента
Система SHALL принимать через существующий admin upload-эндпоинт обложки, видео (mp4, webm, mov, m4v) и WebVTT-субтитры (vtt) с проверкой соответствия расширения и content-type. Инфраструктурный лимит тела запроса MUST быть не менее 200 МБ (видео топиков 50–200 МБ).

#### Scenario: Загрузка видео
- **WHEN** администратор загружает mp4-файл размером 150 МБ
- **THEN** файл принимается хранилищем, возвращается публичный URL для сохранения в сущности

#### Scenario: Отклонение файла недопустимого типа
- **WHEN** администратор загружает файл, content-type которого не соответствует заявленному расширению
- **THEN** возвращается 400 (cross-check расширения и content-type не пройден)
