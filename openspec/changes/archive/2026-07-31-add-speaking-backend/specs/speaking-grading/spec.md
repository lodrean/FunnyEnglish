# Delta spec: speaking-grading (change add-speaking-backend)

## Purpose

Рабочее место учителя: очередь (inbox) practice-записей учеников и оценивание по рубрике с автоматическим усреднением балла и статус-машиной. Детали реализации — `docs/SPEAKING_TRAINER_SPEC_PART1.md` v1.0.

## ADDED Requirements

### Requirement: Grading inbox
Система SHALL предоставлять администратору (ROLE_ADMIN) пагинированный список practice-записей с фильтрами по статусу (NEW/REVIEWED), ученику, топику и диапазону дат (включительно). Сортировка по умолчанию — от новых к старым; размер страницы MUST быть ограничен 100. Каждый элемент SHALL содержать данные ученика (id, email, display name), топика, аудио-URL, длительность, статус и оценку (если есть). Не-администратор MUST получать 403.

#### Scenario: Фильтрация новых записей
- **WHEN** учитель запрашивает inbox с фильтром `status=NEW`
- **THEN** возвращаются только неоценённые записи с пагинацией (totalElements/totalPages)

#### Scenario: Обычный пользователь не имеет доступа
- **WHEN** пользователь с ролью USER запрашивает grading inbox
- **THEN** возвращается 403

### Requirement: Оценивание по рубрике
Система SHALL позволять администратору оценить practice-запись по рубрике из 4 критериев (grammar, vocabulary, pronunciation, fluency), каждый — целое от 1 до 10, с опциональным комментарием. Итоговый балл `total` SHALL вычисляться автоматически как среднее арифметическое критериев (единый источник правды — на уровне БД). В той же транзакции статус записи SHALL перейти NEW → REVIEWED. Повторное создание оценки для уже оценённой записи MUST быть отклонено с 400.

#### Scenario: Первая оценка
- **WHEN** учитель выставляет оценки 7/8/6/7 с комментарием на NEW-запись
- **THEN** создаётся оценка с total = 7.00, запись переходит в REVIEWED, фиксируется reviewer

#### Scenario: Повторная оценка отклоняется
- **WHEN** учитель пытается создать оценку (POST) для уже оценённой записи
- **THEN** возвращается 400 с подсказкой использовать редактирование (PUT)

#### Scenario: Невалидные баллы
- **WHEN** учитель отправляет критерий вне диапазона 1..10
- **THEN** возвращается 400, оценка не создаётся, статус записи не меняется

### Requirement: Редактирование оценки
Система SHALL позволять администратору редактировать существующую оценку (критерии и комментарий); при этом `total` пересчитывается автоматически, reviewer заменяется текущим администратором, дата редактирования фиксируется (аудит), а статус записи остаётся REVIEWED. Редактирование несуществующей оценки MUST возвращать 404. Удаление оценки API SHALL не предусматривать; обратный переход статуса REVIEWED → NEW SHALL быть невозможен.

#### Scenario: Редактирование оценки
- **WHEN** учитель изменяет критерии ранее выставленной оценки
- **THEN** оценка обновляется с пересчитанным total и новым updatedAt, статус записи остаётся REVIEWED

#### Scenario: Редактирование без оценки
- **WHEN** учитель пытается отредактировать оценку записи, которая ещё не оценена
- **THEN** возвращается 404
