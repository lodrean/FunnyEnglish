So to Speak — текущий пользовательский опыт

02Флоу ученика — как он устроен сейчас

Сквозной путь от первого запуска до получения оценки. Ядро продукта — двойной режим ответа голосом.

Вход и онбординг
Splash → 3 статичных слайда ценности (видео / тренировка вслух / отправка учителю). Регистрации на входе нет — гость сразу попадает в библиотеку.
Библиотека тем вкладка
Список ElevatedCard: градиентный тайл 64dp с инициалами, бейдж «N ПРОЙДЕНО» / «НОВАЯ», прогресс-бар темы, chevron. Заголовок + подзаголовок сверху.
Топики темы
Список топиков выбранной темы, переход к видео или сразу к вопросам.
Видео
Плеер (Media3 на Android), переключатель «С субтитрами / Без», полный транскрипт под плеером с пословной подсветкой, полноэкранный режим, CTA «Перейти к вопросам» — доступен всегда.
Вопросы
Hero-карточка активного вопроса («Вопрос 1 из N») + компактные строки остальных. Ниже — выбор режима: Training для всех, Practice за гейтом для гостя.
Training 3 попытки
Одна запись на все вопросы. Таймер-кольцо с эскалацией 80с → 50с → 30с и цветом уровня. Прослушивание без удаления, авто-✅ с анимацией. После 3-й попытки — CTA «Перейти к практике / В библиотеку / Заново».
Practice 30 сек
Одна запись на все вопросы, без прослушивания. Автостоп → автоматическая отправка учителю. Выход во время записи — с диалогом подтверждения.
Отправки вкладка
Карточки со статусом NEW / REVIEWED, чип итогового балла, разбор по рубрике: грамматика, лексика, произношение, беглость (1–10) + комментарий. Повтор отправки при оффлайне.
Профиль вкладка
Аватар-инициалы, три стат-карточки (отправки / темы пройдено / дней с записью), переключатель темы оформления, выход. Для гостя — заглушка с CTA регистрации.

03Визуальный язык «Playful Coach»

Дизайн-система живёт в токенах (W3C DTCG) и генерируется сразу в Kotlin для приложения и в TS/CSS для админки — HEX совпадают 1:1. Выбранный владельцем вариант B из трёх презентованных направлений.

Характер системы

Округлый дружелюбный шрифт Nunito (400–800), шкала Major Third, минимум 14sp, межстрочный 1.5 для читаемости. Пастельная игровая палитра без «стиков и гемов». Карточки без рамок, радиус 22, мягкие тени с индиго-подтоном. Таймер — моноширинные tabular-цифры в кольце прогресса.

Характерные решения

• Кнопка записи — не круг, а squircle 22dp с «жёсткой» оттопыренной тенью, при нажатии схлопывается.
• Запись — дружелюбный персиковый, а не тревожный красный: красный закреплён за ошибками.
• Уровни таймера 80/50/30 кодируются цветом: синий → фиолетовый → персиковый.
• Игровой overshoot- easing на подтверждении попытки; обязательная поддержка reduce-motion.
• Задокументированные WCAG-исправления контраста (в т.ч. в тёмной теме).
• Адаптивность: нижняя панель на компактных экранах, rail — на широких; ограничение ширины контента.

04Сильные стороны текущего UX

Единый источник правды

Токены собираются из одного JSON в код приложения и админки — бренд не расползается между платформами.

Guest-first без тупиков

Видео и Training доступны без регистрации; закрытые зоны оформлены гейтами с понятным CTA, а не заглушками-ошибками.

Эмпатичная запись голоса

Персиковая кнопка, уровни таймера, waveform, честное обещание «записи не покидают устройство» в Training.

Покрытие состояний

Скелетоны загрузки, empty-state с CTA, ошибки с повтором, рационал разрешения микрофона, оффлайн-retry отправок.

Дисциплина доступности

Контрастные пары исправлены и задокументированы, reduce-motion, tabular-nums,语义-разметка тестов.

Адаптивный каркас

Bottom bar / NavigationRail по ширине окна, ограничение ширины контента, полноэкранное видео с учётом вырезов.

05Точки роста — что ограничивает опыт

Приоритеты выставлены по влиянию на ценностную петлю продукта и частоте контакта пользователя с проблемой.

  • ВысокийРазрыв петли обратной связи. Оценка учителя — ключевая ценность, но о новой оценке пользователь узнаёт, только если сам откроет вкладку «Отправки». Экран «Сообщения» существует в коде, но в навигацию не ведёт ни один путь; там же «висит» недостижимый экран настроек.
  • ВысокийНавигация «назад» только системная. На всех флоу-экранах стрелки в аппбаре убраны — на телефоне жест приемлем, на desktop/WASM возврат менее очевиден; новому пользователю трудно сориентироваться в глубине флоу.
  • СреднийОднородная библиотека. Все темы выглядят одинаково: градиентный тайл + инициалы. Нет обложек и иллюстраций, слабая эмоциональная дифференциация — а это первый экран продукта.
  • СреднийМотивационный слой не раскрыт. Статистика профиля — три числа без динамики; игровой потенциал дизайн-системы (кольца, уровни, стрики) в интерфейсе почти не задействован.
  • СреднийСтатичный онбординг. Три слайда с иконками не показывают сам продукт — ни видео, ни демо записи голоса, ни того, как выглядит оценка.
  • НизкийМелкие противоречия. Emoji-иконка 📬 в гостевом гейте вопреки собственной дисциплине дизайн-системы; CTA к вопросам доступен до просмотра видео без мягкой подсказки; нет признака прогресса по отдельным вопросам внутри одной записи.

06Учительская сторона (admin-web)

React 18 + MUI v6, те же токены. Функционально полно: дашборд, CRUD контента Speaking, грейдинг, пользователи, аналитика, клиентские логи.

Контент

Библиотеки → темы → топики: списки и редакторы видео, субтитров, вопросов.

Grading

Inbox записей → детальная оценка: 4 слайдера рубрики 1–10, итоговый балл, комментарий.

Наблюдение

Дашборд, аналитика, пользователи, клиентские логи для отладки.

07Что это значит для редизайна

Первичный вывод о границах изменений — до выбора направления.

Сохранить — это работает

  • Двойной режим Training / Practice и правила попыток
  • Guest-first и механику гейтов
  • Токены, палитру и шрифт как основу (эволюция, а не смена)
  • Покрытие состояний и a11y-дисциплину
  • Статусную модель отправок и рубрику оценки

Зона улучшений

  • Довести петлю ценности: уведомление об оценке, живой разбор
  • Эмоциональный первый экран: обложки тем, витрина библиотеки
  • Мотивационный слой: прогресс, стрик, уровни
  • Онбординг с живым превью продукта
  • Ориентация в флоу: понятный возврат назад, настройки в UI
