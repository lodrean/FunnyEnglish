# Proposal: add-training-self-scoring

## Why

Аудит 2026-08-29 (F-E, `docs/research/PROJECT_AUDIT_2026-08-29.md`): самооценка в Training даёт
смысл 3 попыткам 80→50→30 — сейчас ученик после попытки не знает, что улучшать в следующей.
Транскрипт видео топика (WebVTT с таймингами) уже есть, поэтому эталонный ответ не требует
нового контента.

Решение владельца 2026-09-13 (DECISIONS_BATCH_2026-09-08 #3): **вариант A** — эталон = транскрипт
видео топика (WebVTT), карточка самооценки после попытки, backend-работы ноль. Критерии чеклиста
выбраны владельцем 2026-11-22: 4 критерия по рубрике учителя (grammar/vocabulary/pronunciation/
fluency) — ученик заранее видит те же измерения, по которым его оценят в Practice.

Примечание к формулировке bd: комментарий задачи ссылается на «Part 2 §4.1.1», но §4 — это
контракт VoiceRecorder; самооценка семантически относится к §2.5 (MVI Training) и §5
(Training-режим) — правятся эти секции.

bd: `FunnyEnglish-h3l.5` (эпик `FunnyEnglish-h3l`).

## What Changes

- **Карточка самооценки после попытки** (`SelfScoringCard` на TrainingScreen, между rec-зоной и
  списком попыток): появляется после каждой сохранённой попытки; содержит (а) прослушивание
  своей записи (существующий `AudioPlayer`/`playingRecordingPath` + `PlaybackWaveform`),
  (б) «Эталонный ответ» — полный текст транскрипта видео топика (`subtitleUrl` →
  `getTextResource` → `WebVttParser`, паттерн VideoViewModel; статичный текст для чтения, без
  karaoke-подсветки; секция скрывается, если у топика нет субтитров), (в) чеклист 4 критериев
  по рубрике учителя: Грамматика / Словарь / Произношение / Беглость, (г) CTA «Готово» /
  «Пропустить».
- **Персист самооценки**: `RecordingMeta.selfScore: RecordingSelfScore?` (`checks: List<Boolean>`
  + `scoredAtEpochMs`), `RecordingStore.updateSelfScore`; `ignoreUnknownKeys` даёт обратную
  совместимость со старыми метаданными; живёт в рамках TTL 30 дней записи (Part 2 §5.1).
- **Сводка в списке попыток**: чип «N/4» на карточке попытки, если самооценка сохранена;
  повторное открытие карточки самооценки — по тапу на попытку.
- **Инварианты**: ✅ «попытка принята» остаётся автоматическим, чеклист ничего не гейтит
  (правила попыток §5.3 не меняются); на 3-й попытке карточка сосуществует с финальными CTA;
  «Начать заново» удаляет записи вместе с самооценками.

## Impact

- **Affected specs**: `docs/SPEAKING_TRAINER_SPEC_PART2.md` → v1.10 (§2.5 MVI-контракт,
  §5.3 UI-абзац, новый §5.4). Новая capability `training-self-scoring` (delta ниже).
- **Сверка контрактов спек** (перед фазой реализации): Part 1 (backend) — изменений нет
  (вариант A: ноль backend-работ); Part 3 (admin-web) — не затронута; PRD Story 4 описывает
  правила попыток, пост-попыточный экран не описывает — противоречий нет, правка PRD не
  требуется; DESIGN_SYSTEM_SPEC — токены не меняются, карточка строится на существующих
  токенах/компонентах (`SpeakingShapes.Card`, `PlaybackWaveform`, `SpeakingIcons.CheckCircle`).
- **Affected code**: `composeApp` — `storage/RecordingStore.kt`, `data/SpeakingRepository.kt`,
  `viewmodel/TrainingViewModel.kt`, `screens/TrainingScreen.kt`,
  `localization/Strings.kt`; тесты commonTest (`TrainingScreenTest`, `RecordingStoreTest`);
  Maestro-флоу `speaking_training.yaml` (карточка сдвигает список попыток — добавить scroll).
- **Не меняется**: backend, admin-web, маршруты `AppScreen`, guest-гейты, правила попыток
  80/50/30, Practice-флоу, шоукейс (компонент экранный, не переиспользуемый; токены не
  добавляются).

## Non-goals

- Синхронизация подсветки транскрипта с записью ученика (запись 30–80 с ≠ тайминги видео) —
  транскрипт статичен для чтения.
- Тап по словам транскрипта/WordBook в Training (остаётся в VideoScreen, bd h3l.13).
- Отправка самооценки учителю/backend, влияние самооценки на оценки/гейты/стрик.
- Новые дизайн-токены или секции шоукейса.
- Модельный ответ от учителя (вариант B — поле Topic.modelAnswer) — отклонён владельцем
  2026-09-13.
