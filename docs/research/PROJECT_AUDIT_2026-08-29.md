> Все утверждения подтверждены чтением файлов; пути приведены как доказательства.

## 0. Резюме (TL;DR)

**Состояние проекта необычно здоровое для соло-разработки**: версионированная дизайн-система с WCAG-обоснованиями (tokens.json v1.3.1), 4 pixel-аудита соответствия мокапам, 8 живых тестовых наборов, дисциплина спек (SDD + OpenSpec). Ядро speaking-тренажёра реализовано полностью по PRD и работает на 3 платформах (Android, Desktop, WASM).

**Главные риски сосредоточены вне ядра:**

1. **~9 000 строк мёртвого кода** — 8 неподключённых feature-модулей, 3 параллельные дизайн-системы, ~7 000 строк legacy backend (геймификация/тесты до пивота). Живой код гниёт и расширяет attack surface.
2. **Ручная навигация без бэк-стека** (`App.kt`, 732 строки) — источник двух уже случившихся продакшн-багов; deep-link и системный «назад» невозможны.
3. **Admin Dashboard показывает вымышленные данные** (`userGrowth` уходит в минус, дельты хардкод) — главная страница админки выглядит сломанной.
4. **Нет петли возврата ученика**: ученик не узнаёт об оценке, пока сам не зайдёт в «Мои записи»; после отправки Practice топик для него мёртв (409-гейт без повторной попытки).
5. **Ручной конвейер контента**: субтитры .vtt размечаются вручную, транскодинга нет — наполнение контентом упирается в труд учителя.

**Топ-5 по соотношению ценность/трудоёмкость:**

| # | Действие | Часы | Эффект |
|---|---|---|---|
| 1 | Починить Dashboard админки (убрать моки, реальные метрики или empty state) | 4–6 | Админка перестаёт выглядеть сломанной |
| 2 | Удалить мёртвые DS-слои и feature-модули (~9k строк) | 6–10 | −30% когнитивной нагрузки, убрать источник дрейфа |
| 3 | Email/push «Ваша запись проверена» (EmailService уже есть) | 8–16 | Главный драйвер возврата; закрывает метрику PRD «REVIEWED за 48ч» |
| 4 | Закрыть 3 открытых P3-расхождения с мокапами (bd `0zl`, `xic`, `c47`) | 6–10 | Design conformance 100% |
| 5 | Разрешить повторную Practice после REVIEWED (требует решения по спеке) | 6–10 | Петля роста навыка «оценка → новая попытка» |

## 1. Архитектура

### 1.1. Фактура

**Модули** (`settings.gradle.kts`, 13 модулей): `:backend`, `:shared`, `:composeApp`, `:app`, `:core`(+3 подмодуля), `:feature-api`, 7 × `:feature-*`, `:design`. Есть `build-logic` с 8 convention-плагинами, но они **не применяются** — composeApp собирает конфиг вручную (280 строк `composeApp/build.gradle.kts`).

**composeApp — монолит**: 78 kt-файлов / 13 962 строки в commonMain. `app/screens/` — 15 файлов / 5 269 строк (крупнейшие: `TrainingScreen.kt` 728, `VideoScreen.kt` 689, `PracticeScreen.kt` 632). `App.kt` — 732 строки: DI-старт, тема, онбординг, вся навигация, обе нави-рейки (~120 строк дублирующего кода), два вложенных `AnimatedContent` с копипастой transition.

**Навигация**: `sealed class AppScreen` (14 экранов) + один `mutableStateOf`, **бэк-стека нет вообще**, параметры `(topicId, libraryId, libraryTitle)` пробрасываются вручную через 5 переходов. Уже два продакшн-бага этой схемы (грабля №36, онбординг-навигация).

**Backend**: классический layering (24 контроллера, 24 сервиса, 28 репозиториев, 31 сущность, 23 Flyway-миграции). Speaking-стек компактен и чист (`SpeakingContentService` 228 строк, `PracticeSubmissionService` 155). God-сервисы — всё legacy (`AdaptiveLessonService` 544, `QuestionService` 511).

**shared**: `SoToSpeakApi.kt` — 321 строка, 23 метода на все эндпоинты. Backend зависит от shared-моделей (грабля №51) — скрытая связность server→client.

**CI/CD**: 8 workflow (1 374 строки), дублирование джоб между `ci.yml`/`tests.yml`/`quality-check.yml`. Деплой: ghcr → Timeweb VPS, docker compose + Caddy.

**Тесты**: backend 14 тест-файлов, composeApp desktopTest 22 файла, admin vitest 26 файлов, Playwright (admin + e2e-cmp), Maestro 15 flows, Newman, Dropshots (но **0 golden-эталонов в репо** — гейт фактически ручной). **detekt объявлен в корне, но не подключён ни к одному модулю** — `config/detekt/detekt.yml` мёртв.

**Опровержение устаревшего техдолга**: admin-web `tsc --noEmit` прогнан в этой сессии — **0 ошибок** (запись про «37 ошибок» в memory.md устарела, починено 2026-08-07, грабля №83).

## 3. Функционал

### 3.1. Карта реализованного

**Ядро speaking (KMP)**: Library (pull-to-refresh, скелетоны) → Topics (чипы «пройден/новый») → Video (Media3, fullscreen, WebVTT-транскрипт с пословной подсветкой, replay) → Questions → Training (3 попытки 80/50/30 с, локальные записи, переживают перезапуск) / Practice (30 с, мин. 5 с, автоотправка, retry, гейт 409) → MySubmissions (статусы NEW/REVIEWED, карточка оценки 4 критерия + комментарий). Плюс: auth + email-верификация, гостевой режим с аналитикой, профиль, тема, сквозное логирование.

**Backend**: speaking CRUD + grading inbox с фильтрами, multipart upload, guest-events, client-logs, media upload в S3/MinIO.

**Admin-web**: Dashboard, Speaking (Libraries/Topics/TopicEditor + MediaUploader), Grading (Inbox + Detail + рубрика), Users, Analytics (реальная гостевая аналитика), ClientLogs, Settings.

**Платформы**: Android — полный (запись AAC/m4a). WASM — видео через DOM-оверлей, запись — стаб. iOS/Desktop — стабы.
