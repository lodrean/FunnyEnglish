3.3 Как откатиться

Каждая версия — самостоятельный самодостаточный файл; отката достаточно копированием. Полный снапшот V1 хранится в deliverables/archive/ и сверен по sha256 с активными файлами (см. §5.4).

:: вернуть активные файлы из снапшота V1 copy /Y "deliverables\archive\V1 So to Speak-Бесконечный холст.html" "deliverables\" copy /Y "deliverables\archive\V1 So to Speak-Интерактивный прототип.html" "deliverables\" :: проверить целостность после отката certutil -hashfile "deliverables\V1 So to Speak-Бесконечный холст.html" SHA256

3.4 Откат на уровень концептов

Если направление A нужно пересмотреть: витрины B и C открываются напрямую из sotospeak-redesign/. Правило версионирования: любая будущая правка HTML сначала копирует активную версию в archive/, затем создаётся V2; снапшоты не редактируются никогда. Это гарантирует возврат к любой промежуточной точке.

04Инструкция передачи и сопровождения

4.1 Как открыть

  • Холст и прототип — самодостаточные HTML: двойной клик в любом браузере, интернет не нужен, внешних запросов нет (проверено, §5).
  • Холст: горизонтальная прокрутка; экраны показаны в масштабе 78%, стрелки = переходы.
  • Прототип: на экране шире 1080px справа видно панель шагов сценария; на телефоне рамка разворачивается на весь экран.

4.2 Сценарий сквозного прохода прототипа

  • Темы → «Путешествия» → топик → видео (кнопка play меняется на паузу, полоса прогресса идёт) → «Перейти к вопросам».
  • «Training · 3 попытки» → кнопка записи: таймер идёт ускоренно (≈×7), волна дышит; стоп → попытка засчитана → «Следующая попытка» (цвет уровня меняется 80→50→30) → после третьей финал → «Перейти к практике».
  • Practice → запись → автоотправка → «Запись у учителя» → оранжевый бейдж «1» на вкладке «Отправки» → открой вкладку, бейдж гаснет.
  • Профиль → сегмент «Тёмная» перекрашивает интерфейс; «Настройки» → тумблеры переключаются.

4.4 Зоны ответственности

  • Владелец продукта — контент, правила попыток, финальная интеграция в Compose-приложение (макеты являются спецификацией, не производственным кодом).
  • Разработка — перенос токенов и экранов в Kotlin/Compose по карте §4.3; источник токенов — tokens.json, генерация уже настроена в репозитории.
  • Дизайн-итерации — по правилу версий §3.3; следующий логичный шаг: V2 с онбордингом и гостевыми гейтами (см. §6).

5.3 Симуляция нештатной ситуации

В копию прототипа внесена ошибка: пять переходов data-go="questions" заменены на несуществующий экран "questoins". Валидатор обнаружил все пять, вывел перечень и вернул код exit 1. Контрольный повтор на оригинале — PASS. Запасной план срабатывает: регресс навигации ловится до передачи пользователю.2

5.4 Проверка процедуры отката

Снапшоты созданы и сверены с активными файлами по sha256: СОВПАДАЮТ ×2 (холст, прототип). Возврат из archive/ командами §3.3 восстанавливает состояние V1 бит в бит; реестр сумм V1-checksums.sha256 позволяет проверить любой файл независимо.

5.5 Контроль качества оформления

  • Иконки — только inline SVG (линейные, stroke 1.6–2.2); emoji как элементы интерфейса отсутствуют (проверено полным отсутствием <img> и внешних ссылок).
  • Контраст: белый текст размещён только на #3B6FD4 и темнее; на персиковом #FF9F6B — тёмный #5C2E12; статусы через светлые контейнеры с тёмным текстом.
  • Состояния: hover/active на кнопках и вкладках, запись/пауза, загрузка с индикатором, финальное подтверждение, бейдж уведомления, пустой прогресс тем.
  • Вьюпорты: прототип адаптивен (1080px+ панель шагов, 760–1080 центр, <760 полноэкранный телефон); холст горизонтально скроллится на любой ширине.
  • Движение уважает prefers-reduced-motion.

2 Рабочий черновик с внесённой ошибкой намеренно сохранён в .openclaw/tmp/proto-broken.html как артефакт теста (удаление заблокировано политикой безопасности среды); он не входит в пакет передачи и может быть удалён вручную.
